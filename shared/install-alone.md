**An install the run makes itself stands alone in its call**: no other command
before it or after it, and no change into the project's directory in it either —
where one is needed, that is a call of its own before the install — since the
hook writes the line under `Installed outside the project` only for an install
that stood alone, the call's exit being the install's only then; no pipe, and no
redirection that sends its standard or its error output into a file or to
`/dev/null`, `2>&1` being none; and not with `run_in_background`. Where it is
moved to the background all the same, at the limit of its call, it did not
finish, as "When a command does not answer" says.

**What the report says the package manager did besides is what the whole
output shows, and nothing assumed.** The output is read to its end before
the report is written — where it did not come back whole, the file the
result names — and what it does not show is not said. Before the install and
after it, the run reads the folders for browsers that "Whether it worked is read
off the result" names for this system, and the one a vendor's setting names
where one is set, and the report names what came into them: an install can
download a browser into one of them inside its own call.
