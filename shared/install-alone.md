**An install the run makes itself stands alone in its call**, since 24
October 2026, decision (2) of the roadmap entry of that date on how an
install is recorded: no other command before it or after it, and no change
into the project's directory in it either — where one is needed, that is a
call of its own before the install — since the hook writes the line under
`Installed outside the project` only for an install that stood alone, the
call's exit being the install's only then; no pipe, and no redirection that
sends its standard or its error output into a file or to `/dev/null`,
`2>&1` being none; and not with `run_in_background`. Where it is moved to
the background all the same, at the limit of its call, it did not finish,
as "When a command does not answer" says. Runs 2a and 4 of 23 October 2026
ran `brew install gitleaks 2>&1 | tail -5`, as point 8 of the roadmap
entry of 24 October 2026 on the six closing runs records.

**What the report says the package manager did besides is what the whole
output shows, and nothing assumed.** The output is read to its end before
the report is written — where it did not come back whole, the file the
result names — and what it does not show is not said: run 4 reported that
brew "also fetched its own index and cleaned up unasked", which its cut
output never showed. Before the install and after it, the run reads the
folders for browsers that "Whether it worked is read off the result" names
for this system, and the one a vendor's setting names where one is set, and
the report names what came into them: run 2a's `npm install -g
@mermaid-js/mermaid-cli` downloaded Chrome into `~/.cache/puppeteer` inside
the install call, which its report named as a download on first use.
