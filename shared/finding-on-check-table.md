- **Hand it to the check setup** if its object is `docs/agents/checks.md` — a
  status, a reason that no longer holds, a target, a duration, the line
  `runner:`, the section on what the checks do not cover. It is neither fixed
  on the spot nor filed: only the check setup writes that file, so call
  `setup-checks` for that class, on the branch of the task — for the class the
  finding names, for the class whose row it concerns where it names none, and
  otherwise for the table. It reads the two records, on installing and on the
  dependency file, and fills the class or writes the cell in its form. A
  finding about a row the user switched off, one reading `skipped (user)`, is
  not answered by a run alone: step 4 of `build-work` says how they are asked,
  and that with nobody there the row stays and the run's report names it.
  What the check setup commits on the way is read by a second round of the
  review, like any commit made after the first.
